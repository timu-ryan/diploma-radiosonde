# 2. Архитектура, хранение данных и программные интерфейсы

## Путь одного запроса

Браузер получает список станций и доступных прогонов. После выбора параметров он запрашивает геометрию планшета и прогноз. Fastify проверяет сессию, затем валидирует станцию либо пару координат и время. Сервис расчёта разрешает место старта, выбирает прогон, загружает нужные поля и передаёт в интегратор функции выборки ветра. Интегратор возвращает подробный путь и строки для бланка. Следом сервис вычисляет интервалы нахождения в коридорах и отбирает значения для аэрологической диаграммы. Все эти результаты входят в один ответ для экрана. [Сборка приложения](../project/packages/server/src/app.ts) · [Сервис прогноза](../project/packages/server/src/forecast/service.ts)

| Компонент | Ответственность | Причина выделения |
|---|---|---|
| Клиент React, TypeScript, Vite, Tailwind | Состояние формы в URL, запросы, масштабирование, синхронная подсветка строк, скачивание | Браузер обслуживает взаимодействие. Один и тот же расчёт доступен человеку и системе-интегратору. |
| Сервер Fastify | Авторизация, обработка HTTP, оркестрация прогноза, доступ к файлам и БД | Клиенту достаточно итоговых точек и чертежа, без загрузки всего множества полей. |
| Общий пакет TypeScript | Типы, константы, геодезия, временны́е окна, термодинамические функции и генерация SVG | Один код задаёт масштаб, систему единиц и геометрию для экрана и печати. |
| Файловая подсистема | XML станций и прогнозные поля в каталогах прогонов | Уровень и срок адресуются именем файла. Двоичное поле можно читать по индексу узла. |
| MySQL / MariaDB | Пользователи, ключи доступа и история выдачи | Права и учёт выданных продуктов сохраняются между запусками. |

![Компоненты сервиса и потоки данных](../diagrams/architecture.png)

**Сценарий выдачи.** Запрос бланка заново передаёт место, время и вариант в серверный расчёт. Сервер формирует текст или SVG. После успешного расчёта и формирования продукта обработчик пытается записать выпуск в журнал. Поэтому запись означает обработанную сервером выдачу. Она не подтверждает печать, вручение либо завершённое сохранение PNG в браузере. Запись для обычного просмотра прогноза отсутствует. Для воспроизводимой выгрузки через API можно явно задать идентификатор прогона. [Маршруты выдачи](../project/packages/server/src/routes/api.ts)

## Жизненный цикл данных прогноза

При запуске реестр читает станционные XML и подготавливает геометрию в памяти. Из 106 файлов комплект даёт 105 станций с координатами. Каталог полей сканирует папки вида ГГГГММДДЧЧ, распознаёт только известные изобарические уровни и ведёт перечень сроков отдельно для каждого уровня. Повторная проверка каталога ограничена интервалом 15 с и опирается на отметки изменения папок. Поля, которые уже читались, удерживает LRU-кэш. При лимите 120 полей и размере 167 040 байт потенциальный объём самих буферов составляет около 19,1 МиБ, сверх которого расходуется память процесса. Это расчёт по структуре данных, а не измерение расхода памяти сервера. [Каталог](../project/packages/server/src/grib/catalog.ts) · [Чтение и кэш](../project/packages/server/src/grib/reader.ts)

При настроенном токене фоновый процесс спрашивает у поставщика актуальный прогон и скачивает недостающие файлы. Для полного набора предусмотрены 17 уровней и 23 срока от +6 до +72 ч через 3 ч, всего 391 сочетание. Загрузка во временный каталог и последующее переименование позволяют публиковать подготовленную версию целиком. Ответ 404 для отдельного поля допускает неполный набор. Сетевая ошибка оставляет возможность повторить загрузку. По завершении синхронизации применяется политика хранения прогонов. Для воспроизведения примеров в комплекте стенд использует только приложенные файлы. [Синхронизация](../project/packages/server/src/grib/remote.ts)

## Реляционная модель и права

| Таблица | Основные поля | Как используется |
|---|---|---|
| users | id, login, password_hash, is_active, is_admin, can_coordinates, session_version, профиль и даты | Уникальный логин идентифицирует пользователя. Версия сессии позволяет инвалидировать ранее выданные cookie. |
| api_keys | id, user_id, name, prefix, key_hash, created_at, last_used_at | Несколько ключей могут принадлежать одному пользователю. Полное значение показывается при создании. |
| history | id, created_at, user_id, user_login, user_fio, product, variant, station, place, lat, lon, release_at, run_id, api_key_id, api_key_name | Сохраняет снимок реквизитов выпуска и источник запроса. Дата скачивания и время выпуска зонда имеют разные значения. |

Один пользователь может совершить много выдач. В журнал копируются логин, Ф.И.О. и имя ключа на момент выдачи. Удаление пользователя не должно лишать старые записи смысла. В схеме истории отсутствует внешний ключ на users, а удаление ключей владельца выполняет слой хранилища. Совместимость DDL с MariaDB 5.5 учитывается при расширении таблиц. Приложение сравнивает перечень колонок и добавляет недостающие через ALTER. [Таблицы пользователей и ключей](../project/packages/server/src/auth/mysql.ts) · [Таблица журнала](../project/packages/server/src/journal/mysql.ts)

Пароли проверяются через scrypt с солью. Cookie rs_session содержит идентификатор, версию, срок и подпись HMAC. Сервер сверяет активность и версию записи при обращении. Право выпуска по координатам и права администратора проверяются отдельно. Для других сайтов предусмотрен Bearer-ключ, в базе сохраняется его SHA-256. Вход по ключу ограничен маршрутами /api/v1/. Запрос наследует права владельца. Префикс в списке ключей служит для идентификации записи. [Сессия](../project/packages/server/src/auth/session.ts) · [Проверка доступа](../project/packages/server/src/routes/auth.ts) · [Правила учётных записей](../project/packages/server/src/auth/users.ts)

## Интерфейсы и граница контракта

| Задача | Метод и адрес | Представление |
|---|---|---|
| Проверка состояния / справочники | GET /api/health, /api/stations, /api/runs | Состояние, перечень станций и доступные интервалы UTC |
| Геометрия планшета | GET /api/stations/:name/chart?scale=10 | Параметры холста, линии, коридоры как исходные линии и подписи |
| Экранный расчёт | GET /api/forecast | origin, run, stepPeriods, rows, path, crossings, aerology, warnings |
| Выдача с сайта | GET /api/forecast.txt, /api/chart.svg, /api/diagram.svg | Текст, лист со схемой, аэрологическая диаграмма |
| Интеграция | GET /api/v1/stations, /api/v1/runs, /api/v1/trajectory | Стабильный набор полей. В v1 строки называются levels, давление — pressureHpa. |
| Выдача по v1 | GET /api/v1/report.txt, /api/v1/chart.svg, /api/v1/diagram.svg | Те же генераторы продуктов и журналирование |
| Администрирование | /api/admin/users, /api/admin/keys, /api/admin/journal | Изменение учётных записей, выпуск и отзыв ключей, чтение журнала |

Пример параметров для сравнения JSON: station=ARCHNGL, release=2026-11-18T10:20:00Z. У внешнего ответа каждая точка пути несёт время в минутах, высоту в метрах и широту с долготой в градусах. Высотные отметки содержат также азимут, удаление, ветер и температуру. Канонические примеры обоих ответов взяты по одним параметрам. Полный перечень маршрутов, варианты запросов и конфигурация приведены в спецификации проекта.
