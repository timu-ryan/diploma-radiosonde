# Прогноз перемещения радиозонда

Веб-приложение вместо старых растровых схем: считает снос радиозонда по прогностическому полю
ветра Росгидромета, рисует траекторию на планшете аэрологической станции и печатает бланк
«Прогноз перемещения радиозонда».

- **Бэкенд** — Node + Fastify + TypeScript: разбор XML-планшетов станций, чтение двоичного GRIB,
  расчёт траектории, поиск пересекаемых трасс, текстовый бланк и схема в SVG.
- **Фронтенд** — React + Vite + TypeScript + Tailwind: интерактивная векторная схема,
  таблица перемещения, выгрузка бланка и обеих схем, светлая и тёмная темы.

## Быстрый старт

```bash
npm install
# один раз: база пользователей и первый администратор — см. «Пользователи и вход»
npm run user -- admin --admin --coords
npm run dev           # сервер :3001 + Vite :5173 (прокси /api)
```

Открыть http://localhost:5173 и войти.

```bash
npm test              # тесты (vitest)
npm run build         # сборка shared + server + web
npm start             # production: Fastify раздаёт и API, и собранный фронтенд на :3001
```

Сборка и запуск на сервере — [docs/deploy.md](docs/deploy.md).

## Пользователи и вход

Сайт целиком закрыт логином; регистрации нет — учётные записи заводит администратор
в разделе «Пользователи» (`/admin`, ссылка в меню пользователя справа вверху): создать,
выдать права, задать новый пароль, отключить, удалить. Права два:

- **расчёт по координатам** — без него доступен только выбор станции из списка (кнопки
  «Задать координаты» нет, сервер отвечает 403 на `lat`/`lon`);
- **администратор** — управление пользователями.

Кроме Ф.И.О. и примечания, у пользователя записываются почта, организация, филиал
и подразделение (АМЦ/АМСГ) — справочно для администратора, на права они не влияют.

Пользователи хранятся в MySQL/MariaDB, одна таблица `users`; сервер создаёт её сам при старте
и сам дописывает в неё колонки, появившиеся в новых версиях.
DDL совместим и с MySQL 8, и с MariaDB 5.5. Пароли — scrypt с солью (встроенный `node:crypto`).
Сессия — подписанная cookie `rs_session` (HttpOnly, SameSite=Lax) на `SESSION_DAYS` дней;
новый пароль или отключение пользователя закрывают все его сессии сразу.
После 10 неудачных попыток входа подряд логин с этого адреса блокируется на 15 минут.

**Без `DB_URL` сервер не стартует** — чтобы сайт случайно не оказался открыт всем.

### Создание базы

Нужна отдельная база и пользователь с правами на неё (под администратором СУБД):

```sql
CREATE DATABASE rs_site CHARACTER SET utf8mb4;
CREATE USER 'rs_site'@'localhost' IDENTIFIED BY '<пароль>';   -- для удалённого сервера — '%' или IP сайта
GRANT ALL PRIVILEGES ON rs_site.* TO 'rs_site'@'localhost';
```

Если права выдаются выборочно, сайту нужны `SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER`
на свою базу: `CREATE` — для `CREATE TABLE IF NOT EXISTS` при каждом старте (без него сервер
не поднимется, даже если таблица уже есть), `ALTER` — чтобы дописать колонки после обновления.

В `.env`:

```bash
DB_URL=mysql://rs_site:<пароль>@127.0.0.1:3306/rs_site
SESSION_SECRET=<openssl rand -hex 32>
```

Спецсимволы в пароле внутри `DB_URL` кодируются как в URL (`@` → `%40`, `:` → `%3A`).

### Первый администратор и восстановление доступа

```bash
npm run user -- <логин> [--admin] [--coords] [--fio "Иванов И. И."]
```

Пароль спрашивается в терминале. Если пользователь уже есть — ему задаётся новый пароль,
а сам он включается; так же восстанавливается доступ, если пароль администратора забыт.
Логины — латиница, цифры, `.`, `_`, `-`, регистр не важен; пароль — не короче 8 символов.

### Журнал выпусков

Каждое скачивание из меню «Скачать» — бланк `.txt`, бланк со схемой, аэрологическая
диаграмма — записывается в таблицу `history` той же базы: кто (логин и Ф.И.О. на момент
выпуска), когда, что именно, станция или точка по координатам, время выпуска зонда и прогон.
Расчёт для экрана (`/api/forecast`) и отказы (нет прав, нет данных) не записываются. Если
запись в журнал не удалась, файл всё равно отдаётся, а ошибка попадает в лог сервера.

Смотреть журнал — в админке, вкладка «Журнал выпусков» (`/admin/journal`): новые сверху,
фильтр по пользователю, источнику (с сайта или другим сайтом по ключу API — такие записи
помечены названием ключа) и датам (сутки UTC), по 100 записей. Дежурный синоптик и время
вручения в журнал не пишутся — на бланке эти клетки заполняются от руки.

### Загрузка прогнозов с сервера

Если задан `AVIAMET_TOKEN` (в `.env` в корне репозитория, образец — [.env.example](.env.example)),
сервер сам забирает прогоны
([packages/server/src/grib/remote.ts](packages/server/src/grib/remote.ts)):

```bash
# последний прогон
curl -H "AUTHORIZATION: Bearer <token>" "https://aviametserver.ru/sigmet/modules/gmc/getbin.php?latest"
# одно поле: прогон ГГГГММДДЧЧ, уровень гПа, заблаговременность ч
curl -H "AUTHORIZATION: Bearer <token>" -o f.bin \
  "https://aviametserver.ru/sigmet/modules/gmc/getbin.php?d=2026072900&mb=200&fcst=9"
```

- При старте и затем каждые `AVIAMET_SYNC_MINUTES` минут спрашивается `?latest`; последние
  `AVIAMET_KEEP_RUNS` прогонов (шаг 6 ч) скачиваются, если их ещё нет на диске.
- Качаются все 17 уровней из `FL_MB` × сроки +6…+72 ч через 3 ч (391 файл, ≈65 МБ, ≈10 с).
  Файлов, которых нет на сервере (404), прогон просто не содержит.
- Прогон пишется во временную `.ГГГГММДДЧЧ.partial` и переименовывается целиком — недокачанный
  прогон в расчёт не попадает; при сетевой ошибке он будет скачан заново в следующий раз.
- Каталог по умолчанию — `data/`; прогоны сверх `AVIAMET_KEEP_RUNS` из него **удаляются**, поэтому
  не указывайте `DATA_DIR` на папку с данными, которые нужно сохранить.
- Первая загрузка идёт в фоне: сервер отвечает сразу, прогоны появляются в `/api/runs` по готовности.

`.env` читается только при запуске сервера (`npm run dev` / `npm start`); тесты работают
с эталонным прогоном [data/fixtures/2026080700/](data/fixtures/2026080700/). Из `data/` в git
хранится только `fixtures/`; синхронизация этот подкаталог не трогает.

### Планшет станции (XML)

- `Point` — название, координаты (десятичная запятая), индекс ВМО, АМЦ/АМСГ.
- `Scale Value="10|5"` — чертёж в масштабе 10 или 5 км на деление, холст **536×536**,
  центр **(268, 268)** — точка станции.
- Внутри: `Polyline` (`ps="Dot"` — пунктир), `Airway` (с названием трассы), `Label`
  (`angle` — **десятые доли градуса**, против часовой стрелки, как в GDI).
- Чертежи масштабов хранятся независимо и нарисованы отдельно. `Airway` есть только
  в масштабе 10; в масштабе 5 трассы — безымянные `Polyline` и подписи `Label`, поэтому
  пересечения трасс считаются по чертежу масштаба 10.
- На схеме и бланке рисуются линии `Polyline`; если их нет, используются `Airway`.
  При наличии `Polyline` границы `Airway` повторно не рисуются, но используются
  для расчёта пересечений и автоматических подписей трасс.
  Автоматическая подпись добавляется только тогда, когда название трассы отсутствует
  среди готовых подписей `Label`; исходные подписи на разных участках трассы сохраняются.
- Радиус планшета — **10 делений**: 100 км для масштаба 10 и 50 км для масштаба 5,
  то есть 2,68 и 5,36 пикселя на километр. Эти константы собраны в
  [packages/shared/src/levels.ts](packages/shared/src/levels.ts).

Особые случаи, которые обрабатываются: повторяющиеся блоки `Scale` (BARNAUL, BRATSK, CHKURDK,
KOLPASHV, PETRZVDSK, VANAVARA), станции с одним масштабом (KTELNIY, NORILSK), пустые элементы,
заготовка без координат (XXXXX — не попадает в список станций).

### Поле ветра (GRIB2 в двоичном виде)

Сетка 1,25° (288 × 145 точек), направление WE:SN, 4 байта на точку:

```
байт 0      температура воздуха, °C, без знака
байты 1–2   направление ветра (откуда), 0…359; 11-й бит — знак температуры (1 — плюс)
байт 3      скорость ветра, м/с
```

Индекс точки: `offset = (round((lat + 90) × 0.8) × 288 + round(lon × 0.8)) × 4`.
Реализация — [packages/server/src/grib/reader.ts](packages/server/src/grib/reader.ts),
доступны выборка по ближайшему узлу (по спецификации) и билинейная.

Имя файла `mb_300_fcst_006.bin` = уровень 300 гПа, заблаговременность +6 ч; папка `2026080700` —
прогон 00:00Z 07.08.2026. Соответствие «эшелон ↔ уровень» задано таблицей `FL_MB`,
высота уровня = `FL × 30` м.

## Как считается траектория

Подробное описание исходных планшетов, масштабов, алгоритма и формул всех параметров
перемещения — в [«Построение траектории радиозонда и расчёт её параметров»](docs/trajectory-calculations.md).

[packages/server/src/trajectory/compute.ts](packages/server/src/trajectory/compute.ts)

1. Зонд поднимается с постоянной вертикальной скоростью (по умолчанию **5 м/с ≈ 300 м/мин**,
   меняется параметром `ascent` или переменной `ASCENT_RATE_MS`).
2. Шаг интегрирования — 10 с; на каждом шаге ветер берётся **в текущей точке зонда**,
   на текущей высоте и на текущий момент времени:
   - по высоте — **ближайший изобарический уровень**, без интерполяции (посередине между
     уровнями — нижний; ниже нижнего уровня ветер считается постоянным: приземных данных
     в наборе нет);
   - по времени — **срок, действующий в этот момент**, без интерполяции. Каждый срок действует
     ±1,5 ч: +6 ч — с +4,5 до +7,5 ч, +9 ч — с +7,5 до +10,5 ч и т. д.; граница принадлежит
     следующему сроку, при пропуске срока соседние делят промежуток пополам
     ([packages/shared/src/steps.ts](packages/shared/src/steps.ts)). Если подъём пересекает
     границу, срок меняется в полёте — это видно в `stepPeriods` ответа.
   - прогон действует от первого срока − 1,5 ч до последнего + 1,5 ч; из нескольких прогонов
     берётся самый свежий, действующий на время выпуска. Свежий прогон появляется на сервере
     с опозданием, поэтому ближайшие часы обычно считаются по предыдущему.
3. Строки отчёта берутся не с изобарических уровней, а с фиксированной лестницы высот
   бланка — **1500, 3000, 5000, 7000, 9000, 12 000, 16 000 м** (`REPORT_HEIGHTS_M`).
   Лестница обрезается по верхнему уровню прогона. Для каждой высоты считаются: ветер
   (с ближайшего уровня, он же подписан в строке), время подъёма в слое, азимут и удаление от точки выпуска
   нарастающим итогом и смещение в слое — ровно те поля, что есть в бумажном бланке.
4. Дополнительно ищутся **пересекаемые воздушные трассы**
   ([crossings.ts](packages/server/src/trajectory/crossings.ts)). Трасса на чертеже — коридор
   между линиями `Airway` с одним названием (`Т825-1`, `Т825-2`, …). Линии нарисованы
   вручную, поэтому коридор не собирается в многоугольник, а заливается на сетке ≈0,2 км:
   концы, не дотянутые до соседней линии на 4 пикселя, к ней пришиваются, открытые концы
   коридора (до 40 км шириной) замыкаются, всё, куда не дошла заливка снаружи, — внутри
   трассы. На каждый заход в коридор отдаются высоты, время, азимуты и удаления входа и
   конца участка (полярные координаты — от центра планшета станции). Если зонд выпущен
   внутри коридора, вход — 0 м; если не вышел, конец участка — конец рассчитанного пути,
   `exited: false`. В текстовом отчёте неизвестный выход обозначается `XXX`.
5. **Выпуск по координатам.** Вместо станции можно задать точку выпуска (`lat`, `lon`). Она
   рисуется на планшете ближайшей станции, если та не дальше 30 км (`STATION_RADIUS_KM`
   в [shared/levels.ts](packages/shared/src/levels.ts)): точка смещена от центра планшета, путь
   для поиска трасс сдвигается на это смещение. Если станции рядом нет — планшет без чертежа
   с центром в самой точке, трассы не проверяются (об этом есть предупреждение). Ближайшую
   станцию сервер и фронтенд выбирают одной функцией `nearestWithin`.

## Аэрологическая диаграмма

Под схемой строится прогностическая аэрологическая диаграмма в одном из двух видов, как на
flymeteo.org: косоугольная АДК (skew-T log-p, по умолчанию) или прямоугольная АДП (диаграмма
Штюве). Переключатель — над диаграммой; выбранный вид запоминается в адресе (`diagram=`).
Скачать в PNG можно любой вид, не переключая экран, — пунктами «АДК» и «АДП» в меню «Скачать»
(как схемы обоих масштабов). Значения на каждом изобарическом уровне берутся **вдоль
траектории**: в той точке и в тот момент, когда зонд проходит высоту уровня
([trajectory/aerology.ts](packages/server/src/trajectory/aerology.ts)), — то, что «измерит»
прогнозируемый зонд. Уровни выше конца пути берутся в последней точке пути.

Бланк: давление 1050…100 гПа по вертикали, у изобар — высоты (`FL × 30` м), сухие и влажные
(псевдо)адиабаты, линии массовой доли водяного пара 1–24 г/кг, стандартная атмосфера СА-81
(ГОСТ 4401-81). На АДК давление — в логарифмическом масштабе, изотермы наклонены на 45°;
на АДП давление — по `p^κ` (κ = R/cp ≈ 0,286), изотермы вертикальные (−85…+43 °C), сухие
адиабаты — прямые. Виды отличаются только проекцией (`diagramProjection`). Поверх — кривая
температуры и флажки ветра справа (короткое перо 2,5 м/с, длинное 5, треугольник 25; перья —
как в северном полушарии) с подписями «направление/скорость». Формулы и правила построения
каждой линии — ниже, в разделе [«Как строится бланк»](#как-строится-бланк).

Обработка ([shared/aerology.ts](packages/shared/src/aerology.ts)) — всё, что можно получить из
температуры и ветра:

| Что | Как считается |
|---|---|
| Тропопауза | критерий ВМО: первый уровень выше 500 гПа, где градиент ≤ 2 °C/км и средний градиент до уровней в 2 км выше тоже ≤ 2 °C/км; вторая — после слоя толщиной от 1 км с градиентом > 3 °C/км |
| Изотермы 0, −10, −20 °C | пересечения профиля, высота — линейно между уровнями, давление — линейно по ln p; все пересечения снизу вверх; если уже на 850 гПа холоднее — «ниже 1500 м» |
| Обледенение | слой от первой нулевой изотермы до −20 °C — обледенение возможно, если там есть облака |
| Инверсии и изотермии | рост температуры или ΔT = 0 между соседними уровнями ниже тропопаузы, соседние слои одного рода сливаются |
| Максимальный ветер, струйное течение | уровень с наибольшей скоростью; струйное — непрерывный слой ≥ 30 м/с вокруг него, границы интерполируются |
| Болтанка | число Ричардсона по потенциальной температуре и сдвигу ветра между соседними уровнями, Ri < 1 (уровни редкие, сдвиг занижен — порог мягче классического 0,25) |
| VT | T850 − T500 |
| Средний ветер в слое 0–H | для высот отчёта: смещение зонда / время подъёма — при постоянной скорости подъёма это средний по высоте ветер слоя |

**Чего нет и почему.** В прогнозе нет влажности, приземных данных и уровней ниже 850 гПа, а верхний
уровень — 100 гПа (≈16 км). Поэтому не строятся точка росы и относительная влажность, уровень
конденсации и конвекции, кривая состояния и энергия неустойчивости, облачность и обледенение по
облакам, индексы K, CT, TT, SWEAT, грозы по Вайтингу, Фаусту, Фатееву и Лебедевой, ветер «на
круге» и температура 100–1000 м, высоты до 18 км. Температура в файлах целая, поэтому изотермии
и градиенты на тонких слоях огрублены.

Диаграмму на экране и в скачанном файле рисует один код —
[shared/diagram.ts](packages/shared/src/diagram.ts); скачиваемая (`/api/diagram.svg`) всегда
светлая, с шапкой и легендой. Профиль и обработка отдаются в JSON — поле `aerology`
ответа `/api/forecast`.

### Как строится бланк

Каждая линия бланка сначала считается в физических координатах — как список точек
«давление p, температура T», — и только потом переводится в координаты листа проекцией
выбранного вида. Поэтому на АДК и АДП линии физически одни и те же, а выглядят по-разному.
Формулы — в [shared/aerology.ts](packages/shared/src/aerology.ts), сборка линий —
`renderBlank` в [shared/diagram.ts](packages/shared/src/diagram.ts). Линии — ломаные
через рассчитанные точки, всё за пределами поля обрезается.

Постоянные:

| Обозначение | Значение | Что это |
|---|---|---|
| `Rd` | 287,04 Дж/(кг·К) | газовая постоянная сухого воздуха |
| `cp` | 1005,7 Дж/(кг·К) | теплоёмкость сухого воздуха при постоянном давлении |
| `κ` | `Rd / cp` ≈ 0,2854 | показатель адиабаты Пуассона |
| `Lv` | 2,501·10⁶ Дж/кг | удельная теплота парообразования |
| `ε` | 0,622 | отношение молярных масс водяного пара и сухого воздуха |
| `g` | 9,80665 м/с² | ускорение свободного падения |

Температуры в формулах — в кельвинах (T °C + 273,15), если не сказано иное; давление — в гПа.

#### Поле и проекции

Диаграмма — 880 × 784 единиц, поле — 640 × 720 с левым верхним углом в (64, 24);
внизу поля 1050 гПа, вверху 100 гПа. Проекция переводит (T, p) в точку (x, y), ось y
направлена вниз. Обе проекции — в `diagramProjection(kind)`; всё, что рисуется на поле,
обязано проходить через неё.

**АДК (skew-T log p).** По вертикали — ln p, температура сдвинута вправо на столько же,
на сколько точка поднялась, — изотермы идут под 45°:

```
y(p)    = 24 + 720 · (ln p − ln 100) / (ln 1050 − ln 100)
x(T, p) = 64 + 8 · (T°C + 35) + (744 − y(p))
```

8 единиц на градус, в левом нижнем углу −35 °C, на верхней кромке слева направо — от −125
до −45 °C. Это линейное преобразование координат (T, ln p) с постоянным определителем,
поэтому площади на АДК пропорциональны энергии, как на эмаграмме.

**АДП (Штюве).** По вертикали — p^κ, температура не сдвинута, изотермы вертикальные:

```
y(p) = 24 + 720 · (p^κ − 100^κ) / (1050^κ − 100^κ)
x(T) = 64 + 5 · (T°C + 85)
```

5 единиц на градус, от −85 °C у левой кромки до +43 °C у правой. Площади на АДП энергии
не пропорциональны: верхние слои по площади занижены.

#### Изобары и изотермы

- **Изобары** — горизонтальные линии на 1000, 925, 850, 700, 500, 400, 300, 250, 200, 150
  и 100 гПа. Слева подписаны давление и высота уровня `FL × 30` м (`mbToMeters`), а не
  геопотенциал модели.
- **Изотермы** — через 10 °C от −130 до +50 °C, отрезок от (T, 1050 гПа) до (T, 100 гПа);
  0 °C толще остальных. На обоих видах изотерма — прямая. Значения подписаны под полем,
  на АДК — и над ним (там, где наклонные изотермы выходят на верхнюю кромку); на АДП подпись
  сверху повторяла бы нижнюю, её нет.

#### Сухие адиабаты

Так меняется температура ненасыщенной частицы, которая поднимается или опускается без
обмена теплом с окружением. Из первого начала термодинамики для адиабатного процесса
`cp·dT = (Rd·T / p)·dp` следует уравнение Пуассона:

```
θ = T · (1000 / p)^κ          потенциальная температура, К
T(p) = θ · (p / 1000)^κ       температура на сухой адиабате с потенциальной температурой θ
```

Вдоль сухой адиабаты θ постоянна, градиент — `g / cp` ≈ 9,8 °C/км (`potentialTemperature`,
`dryAdiabatTemp`).

Построение:

1. θ берётся через 10 °C: на АДК от −30 до +170 °C, на АДП от −90 до +340 °C — диапазоны
   подобраны так, чтобы линии покрывали поле своей проекции (на АДП в правом верхнем углу,
   +43 °C на 100 гПа, θ ≈ 337 °C).
2. Для каждой θ — 37 давлений от 1050 до 100 гПа с равным шагом по ln p (`pressureSteps(36)`).
3. В каждой точке T(p) по формуле выше, точки (x(T, p), y(p)) соединяются ломаной.

На АДП T линейна по p^κ, поэтому сухие адиабаты — прямые; продолженные, они сходятся
в точке (−273,15 °C; p = 0) за пределами поля.

#### Давление насыщенного пара и насыщающее отношение смеси

Давление насыщенного водяного пара над плоской поверхностью воды — формула Болтона (1980),
T в °C (`saturationVaporPressure`):

```
eₛ(T) = 6,112 · exp(17,67 · T / (T + 243,5))      гПа
```

Насыщающее отношение смеси — сколько килограммов пара на килограмм сухого воздуха может быть
в воздухе при температуре T и давлении p (`saturationMixingRatio`):

```
rₛ(T, p) = ε · eₛ(T) / (p − eₛ(T))      кг/кг
```

Обе величины нужны для линий массовой доли и влажных адиабат.

#### Линии массовой доли водяного пара

Линия значения w — все точки (T, p), где насыщающее отношение смеси равно w. Для неё формулы
выше обращаются: по w и p находится давление пара, по нему — температура (`mixingRatioTemp`):

```
e = w · p / (ε + w)                 w в кг/кг (на бланке — г/кг, делится на 1000)
L = ln(e / 6,112)
T = 243,5 · L / (17,67 − L)         °C, обращённая формула Болтона
```

Построение: w = 1, 2, 4, 7, 10, 16 и 24 г/кг; для каждого — 19 давлений от 1050 до 100 гПа
с равным шагом по ln p (`pressureSteps(18)`), точки соединяются ломаной, значение подписано
у нижнего конца линии.

Как ими пользуются: если на линии лежит точка росы, это фактическое содержание пара в воздухе;
если температура — предел насыщения при этой температуре. Пересечение линии w через точку росы
у земли с сухой адиабатой через температуру у земли — уровень конденсации (правило Норманда).
Влажности в прогнозе нет, поэтому у нас эти линии — только сетка бланка.

Строго говоря, считается отношение смеси r (масса пара к массе сухого воздуха), а подписано
«массовая доля» q (масса пара к массе всего воздуха); `q = r / (1 + r)`, при 24 г/кг разница
меньше 2,5 %.

#### Влажные (псевдо)адиабаты

Так меняется температура насыщенной частицы: при подъёме пар конденсируется и отдаёт скрытую
теплоту, поэтому частица остывает медленнее, чем по сухой адиабате, — около 4–7 °C/км
в тёплом влажном воздухе; вверху, где пара почти нет, наклон приближается к сухому.
«Псевдо» — сконденсированная вода сразу выпадает и дальше в теплообмене не участвует.
Наклон в координатах давления (`moistLapse`), T в кельвинах:

```
dT/dp = (Rd·T + Lv·rₛ) / (p · (cp + Lv²·rₛ·ε / (Rd·T²)))      К/гПа
```

rₛ здесь зависит от текущих T и p, поэтому замкнутой формулы у влажной адиабаты нет —
её интегрируют численно (`moistAdiabat`).

Построение:

1. Начальная температура T₀ задаётся на 1000 гПа: от −20 до +36 °C через 4 °C.
2. От 1000 гПа интегрируется вверх до 100 гПа и вниз до 1050 гПа с шагом Δp = 10 гПа
   (последний шаг укорачивается до границы) методом средней точки (Рунге — Кутта 2-го порядка):

   ```
   k₁ = dT/dp (T, p)
   k₂ = dT/dp (T + k₁·Δp/2, p + Δp/2)
   T ← T + k₂·Δp,   p ← p + Δp           Δp < 0 при подъёме
   ```

3. Обе половины склеиваются в одну ломаную через точку (T₀, 1000 гПа).

#### Стандартная атмосфера СА-81

ГОСТ 4401-81, до 20 км совпадает с международной стандартной атмосферой (`standardAtmosphere`).
H — геопотенциальная высота, м; R = 287,05287 Дж/(кг·К):

```
H ≤ 11 000 м:   T = 288,15 − 0,0065·H
                p = 1013,25 · (T / 288,15)^(g / (R · 0,0065))
H > 11 000 м:   T = 216,65
                p = p₁₁ · exp(−g · (H − 11 000) / (R · 216,65)),   p₁₁ ≈ 226,32 гПа
```

Построение: точки через 250 м от 0 до 16 500 м, пока давление не меньше 100 гПа; подпись
«СА-81» — у точки 15 500 м.

#### Что выбрано, а не задано стандартом

- Размер поля, температурный диапазон, масштаб, шаги линий (θ через 10°, T₀ через 4°, набор
  значений w) и число точек на линии подобраны для читаемости. Общего стандарта на них нет,
  на других бланках (AWS/TR-79/006, flymeteo) они свои — сверять с ними стоит принцип, а не цифры.
- Формула Болтона — насыщение над водой, рассчитана примерно на −30…+35 °C. Насыщения надо
  льдом нет; ниже −40 °C влажные адиабаты и линии массовой доли условные, на рисунке это
  незаметно — пара там почти нет.
- Влажные адиабаты псевдоадиабатические (вода выпадает сразу), как на большинстве бланков;
  обратимая влажная адиабата с удержанием воды не строится.

## API

Всё, кроме `/api/auth/login`, `/api/auth/logout` и `/api/health`, требует входа: без cookie
сессии — 401 `unauthorized`, без нужного права — 403 `forbidden`.

| Метод | Назначение |
|---|---|
| `POST /api/auth/login` `{login, password}` | вход, ставит cookie сессии; 401 — неверные данные, 429 — много попыток |
| `POST /api/auth/logout` | выход |
| `GET /api/auth/me` | кто вошёл и с какими правами |
| `POST /api/auth/password` `{current, next}` | смена своего пароля (другие сессии закрываются) |
| `GET /api/admin/users` | пользователи (только администратор) |
| `POST /api/admin/users` | завести пользователя |
| `PATCH /api/admin/users/:id` | Ф.И.О., почта, организация/филиал/подразделение, примечание, права, вход разрешён, новый пароль |
| `DELETE /api/admin/users/:id` | удалить пользователя |
| `GET /api/admin/journal` | журнал выпусков, новые сверху: `user`, `source` (`site`/`key`), `from`/`to` (ГГГГ-ММ-ДД, UTC, включительно), `before` (id), `limit` (до 500) |
| `GET /api/admin/keys` | ключи API (без самих ключей) |
| `POST /api/admin/keys` `{userId, name}` | выдать ключ — в ответе `key`, единственный раз |
| `DELETE /api/admin/keys/:id` | отозвать ключ |
| `GET /api/stations?q=` | список станций, поиск по названию, коду, индексу ВМО |
| `GET /api/stations/:name/chart?scale=10\|5` | геометрия планшета |
| `GET /api/runs` | прогоны, сроки, уровни, период действия |
| `GET /api/forecast?station=&release=&run=&interp=&ascent=` | расчёт: шапка, таблица уровней, траектория |
| `GET /api/forecast?lat=&lon=&release=…` | то же из точки по координатам вместо станции |
| `GET /api/forecast.txt?…` | тот же расчёт бланком «Прогноз перемещения радиозонда» (UTF-8) |
| `GET /api/chart.svg?station=\|lat=&lon=&release=&scale=&download=1` | готовый бланк со схемой в SVG (чёрно-белый) |
| `GET /api/diagram.svg?station=\|lat=&lon=&release=&kind=&download=1` | аэрологическая диаграмма в SVG (светлая); `kind=skewt` — АДК (по умолчанию), `kind=stuve` — АДП |
| `GET /api/health` | состояние сервиса |

`release` — время выпуска в ISO UTC (`2026-08-07T11:30:00Z`), любое, не только кратное сроку.
Если данных на это время нет, ответ 400 перечисляет доступные периоды. В ответе `usedSteps` —
использованные сроки, `stepPeriods` — какой срок в какую часть подъёма действовал,
`aerology` — уровни вдоль траектории (P, H, T, ветер, время прохождения) и их обработка.

`lat`, `lon` — точка выпуска в десятичных градусах (широта −90…90, долгота −180…180, разделитель —
точка или запятая); задаются только парой и, если указан и `station`, главнее неё. В ответе
`origin` — точка выпуска (`custom` — задана координатами, `dxKm`/`dyKm` — смещение от центра
планшета), `station` — станция, чей планшет использован; её нет, если в 30 км от точки станций нет.
В именах скачиваемых файлов вместо кода станции — координаты: `radiosonde_64.70N_40.60E_20260807_1130.txt`.

Пример:

```bash
curl -c jar.txt -H 'content-type: application/json' \
  -d '{"login":"admin","password":"…"}' http://localhost:3001/api/auth/login
curl -b jar.txt "http://localhost:3001/api/forecast.txt?station=ARCHNGL&release=2026-08-07T11:30:00Z"
```

Текстовый бланк — UTF-8 с переводами строк CRLF: каждая высота занимает одну строку
с ветром, временем подъёма в слое, азимутом, удалением и смещением в слое. Ниже —
строки «Радиозонд будет пересекать трассу … в аз. … на уд. … в слое … в … UTC».
Если выход из трассы не попал в рассчитанную траекторию, его значения заменяются на `XXX`.
Предупреждения о неполноте данных сохраняются в разделе «Примечания».

## API для других сайтов (`/api/v1`)

Для сайтов, которые показывают траектории и диаграммы у себя. Адреса `/api/*` выше меняются
вместе со своим фронтендом, а `/api/v1` — стабильный контракт: поля в ответах только
добавляются, переименовать или убрать что-то можно лишь в новой версии (`/api/v2`).
Типы ответов — в [packages/shared/src/v1.ts](packages/shared/src/v1.ts).

**Доступ.** Администратор заводит для сайта отдельного пользователя (для расчёта по точке
на карте — с правом «Расчёт по координатам») и выдаёт ему ключ в админке, вкладка «Ключи API».
Ключ показывается один раз; сервер хранит только его хеш. Запросы идут **с сервера** другого
сайта с заголовком `Authorization: Bearer <ключ>`. В браузер ключ отдавать нельзя: кто его
увидит, получит тот же доступ. Картинки сервер того сайта получает сам и отдаёт своим страницам.

Запросы по ключу идут от имени владельца ключа и с его правами. Отключение владельца или отзыв
ключа закрывают доступ сразу. Ключ действует только на `/api/v1/*`: админка, смена пароля
и адреса своего фронтенда по ключу недоступны. Скачанные по ключу бланки и диаграммы
попадают в журнал выпусков с пометкой ключа, траектории (`trajectory`) — нет.

| Метод | Назначение |
|---|---|
| `GET /api/v1/runs` | прогоны: `id`, `runTime` и период `validFrom`…`validTo`, на который по прогону можно считать |
| `GET /api/v1/stations` | станции: код (`name`), название, индекс ВМО, АМЦ/АМСГ, координаты |
| `GET /api/v1/trajectory?lat=&lon=&release=` | траектория из точки: `path` — линия для карты (`lat`, `lon`, высота, время), `levels` — строки бланка с ветром и температурой, `crossings` — пересечения трасс, `warnings` |
| `GET /api/v1/trajectory?station=&release=` | то же со станции |
| `GET /api/v1/diagram.svg?…&kind=skewt\|stuve` | аэрологическая диаграмма, SVG |
| `GET /api/v1/chart.svg?…&scale=10\|5` | бланк со схемой, SVG |
| `GET /api/v1/report.txt?…` | бланк «Прогноз перемещения радиозонда», текст UTF-8 |

Каждый элемент `crossings` содержит название трассы `airway`, высоты
`fromHeightM`/`toHeightM` (м), время от выпуска `fromTimeMin`/`toTimeMin` (мин),
азимуты `fromAzimuthDeg`/`toAzimuthDeg` (градусы в диапазоне [0, 360)) и удаления
`fromDistanceKm`/`toDistanceKm` (км). Азимуты и удаления отсчитываются от центра
планшета станции, в том числе при выпуске по координатам рядом с ней.
`exited: true` означает, что зонд вышел из коридора трассы; при `exited: false`
рассчитанный путь закончился внутри него. Во втором случае все поля `to*`
содержат числовые значения конца пути, а не фактического выхода из трассы.

Параметры расчёта — как у `/api/forecast`: `release` (ISO UTC), `station` или пара `lat`/`lon`,
необязательные `run`, `interp`, `ascent`. Ошибки — JSON `{ error, message }`: 401 `unauthorized`
(нет ключа или он недействителен), 403 `forbidden` (у владельца ключа нет права на координаты),
400 `bad_request` / `no_data_for_time` (во втором случае в `available` — доступные периоды),
404 `station_not_found`.

```bash
KEY=rsk_…
curl -H "Authorization: Bearer $KEY" "https://сайт/api/v1/runs"
curl -H "Authorization: Bearer $KEY" "https://сайт/api/v1/trajectory?lat=64.7&lon=40.6&release=2026-08-07T11:30:00Z"
curl -H "Authorization: Bearer $KEY" -o diagram.svg \
  "https://сайт/api/v1/diagram.svg?lat=64.7&lon=40.6&release=2026-08-07T11:30:00Z&kind=skewt"
```

Если сайт открыт под `BASE_PATH`, адреса с ним: `https://aviametserver.ru/zond/api/v1/runs`.
Полный адрес показан на странице «Ключи API».

## Интерфейс

- Без входа — только страница входа. Справа в шапке — меню пользователя: «Пользователи»
  (администратору), «Сменить пароль», «Выйти». Если сессия кончилась (пароль сменили,
  пользователя отключили), при следующем запросе снова открывается страница входа.
- Поиск станции по русскому названию, коду или индексу ВМО.
- Кнопка «Задать координаты» у поля станции (только у пользователей с этим правом) открывает
  поля широты и долготы (подставляются координаты выбранной станции) — расчёт идёт из этой
  точки; «Выпуск со станции» скрывает их.
  Значение применяется по Enter или при уходе из поля; принимаются `64,62`, `-12.5`,
  `64,62 с.ш.`, `40.5E`. Выбор станции в этом режиме подставляет её координаты. Под полями
  видно, на чьём планшете рисуется точка и как далеко она от станции.
- Время выпуска задаётся отдельно: дата — кнопками (сутки, на которые есть данные, обычно 3–4),
  время — полем `чч:мм` в UTC, произвольное (↑/↓ — ±10 мин, с Shift — ±1 ч; «Сейчас» —
  текущее). Кнопки «11:30» и «23:30» меняют только время UTC, сохраняя выбранную дату.
  По умолчанию — текущее время.
- Выноска под полем показывает, по какому прогону и сроку считается выбранное время и когда
  срок действует; если срок сменится в полёте — с какой минуты подъёма; если время не покрыто
  данными — доступный период. Список прогонов обновляется сам по мере загрузки на сервере.
- Переключатель масштаба 100 км / 50 км — над схемой; зум колесом, панорамирование
  перетаскиванием, двойной клик — сброс.
  Промежуточные кольца контрастнее фона в обеих темах; их толщина на экране — 1 пиксель
  независимо от размера схемы и зума, чтобы сетка не исчезала при уменьшении.
  Среднее и внешнее кольца (50 и 100 км в масштабе 10 км), а также основные оси — по 2 пикселя.
- Наведение на точку высоты или строку таблицы подсвечивает их синхронно.
  Линия траектории и точки высот — приглушённые серо-синие в обеих темах.
- Подписи трасс и ориентиров рисуются поверх линий с подложкой цвета фона,
  чтобы текст читался в светлой и тёмной темах.
  Чекбокс «Подписи трасс» управляет названиями из XML и автоматическими подписями
  в обоих масштабах; названия станции и ориентиров остаются видимыми.
- Под схемой — аэрологическая диаграмма с обозначениями и пояснениями под ней, рядом итоги
  обработки и таблица уровней; наведение на уровень диаграммы или строку таблицы подсвечивает
  их синхронно. Обозначения — один список (`diagramLegend`) для экрана и скачиваемой картинки.
- Выгрузки — в меню «Скачать» рядом с формой: бланк перемещения .txt, схема 100 и 50 км,
  диаграмма АДК и АДП — **любой масштаб и любой вид диаграммы скачиваются независимо от того,
  что показано на экране**. Бланк и диаграмму
  рисует сервер (`/api/chart.svg`, `/api/diagram.svg`), браузер только переводит их в PNG
  (бланк — 1800 × 2538, ≈300 dpi A4).
- Светлая тема по умолчанию, тёмная — по кнопке (запоминается в браузере).
- Состояние формы отражается в адресной строке — ссылкой на конкретную схему можно поделиться:
  `?station=ARCHNGL&release=2026-08-07T11:30:00Z&scale=5`, при выпуске по координатам
  добавляются `&lat=64.7&lon=40.6`. Параметр `?theme=dark|light`
  принудительно задаёт тему.

### Бланк со схемой

Скачиваемая картинка — не просто планшет, а лист бланка целиком
([packages/shared/src/form.ts](packages/shared/src/form.ts)), **чёрно-белый**, под печать:

- шапка: заголовок, АМЦ/АМСГ, станция с координатами (при выпуске по координатам — «Точка
  выпуска р/з» с её координатами), дата и время выпуска р/з, прогон и масштаб
  («МАСШТАБ: 1 деление - 5 км»);
- планшет с траекторией: тонкие кольца (пятое — жирное), жирные оси С—Ю и З—В,
  румбы С/В/Ю/З, засечки внутрь окружности через 10°, чёрные кружки с белыми номерами высот;
- таблица в левом нижнем углу: № / Высота, км / Время, мин. / Азимут, град / Удаление, км;
- поля «Время вручения» и «Деж. синоптик». Внешней рамки у листа нет.

Планшет внутри бланка рисует тот же `renderChartBody` в режиме `variant: 'print'`,
чёрно-белой палитрой, без дополнительных радиальных линий и экранных подписей
(азимутов в цифрах, километровых меток колец и автоматически расставленных названий трасс).
Подписи исходного чертежа станции, включая обозначения трасс и ориентиры, сохранены:
на скачиваемых SVG и PNG они рисуются поверх линий с белой подложкой вокруг букв.
Чертёж и траектория обрезаются по внешнему кольцу, чтобы не попадать на поля листа.
Шапка набрана крупным шрифтом с засечками; пропорции листа и размер PNG сохранены.

## Структура

```
packages/shared   типы, константы планшета и уровней, геодезия, форматирование,
                  отрисовка схемы (chart.ts) и аэрологической диаграммы (diagram.ts) в SVG —
                  общая для сервера и браузера; термодинамика и обработка профиля (aerology.ts)
packages/server   Fastify: станции, каталог прогонов, чтение GRIB, расчёт, отчёт,
                  /api/chart.svg, /api/diagram.svg; вход и пользователи (auth/, MySQL),
                  журнал выпусков (journal/)
packages/web      React + Vite: интерактивная схема поверх общей отрисовки, таблица, выгрузка,
                  страница входа, админка пользователей и журнал
```

Схему рисует один и тот же код: сервер отдаёт готовый SVG-документ, а браузер вставляет ту
же разметку внутрь своего `<svg>` и добавляет сверху только слой наведения и зума.

## Замечания к расчёту

- Высоты **уровней прогноза** берутся по формуле спецификации `FL × 30` м (500 гПа → 5400 м,
  300 гПа → 9000 м). Высоты **строк отчёта** — это отдельная лестница бланка
  (1500 … 16 000 м); ветер на них берётся с ближайшего уровня. Обе таблицы лежат рядом
  в [packages/shared/src/levels.ts](packages/shared/src/levels.ts).
- В комплекте данных один прогон и четыре уровня (850, 700, 500, 300 гПа), верхний из них
  9000 м, поэтому отчёт доведён до 9000 м (5 строк вместо 7) — об этом сказано в примечании
  к расчёту. С полным набором (17 уровней, 23 срока) строк будет 7, как в бланке.
- По умолчанию ветер снимается в ближайшем узле сетки, как в спецификации формата;
  `interp=bilinear` включает билинейную интерполяцию.
